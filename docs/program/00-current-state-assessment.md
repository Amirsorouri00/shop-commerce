## 0.3 Structural gaps against MASTER-PROMPT's own definition of done

These are not bugs — they're exactly the kind of finding Phase 0 exists to surface, and they directly seed Phase 1–3 scope:

1. **No B2B/enterprise surface exists at all.** Everything above is B2C-only. `phase-0.3-logistics-feasibility.md` (per Graphify community 35) already describes "Business Line 2: Merchant Fulfillment Platform" and "Business Line 3: Enterprise Import/Export Procurement Desk" as *documented* concepts — none have any code footprint. Phase 1 must decide what, if anything, ships now.
2. **Identity/account model is customer-only and flat.** DB has `customers`/`identities`/`operators` — no `Organization`, `OrganizationMembership`, `MerchantProfile`, `Role`/`Permission` tables. Phase 2 is greenfield here, not a refinement.
3. **Customer-facing exception decisions are missing.** Price-changed and out-of-stock are fully modeled operator-side but the customer has no UI to see/accept/reject them — a direct MASTER-PROMPT Phase 3 violation ("No journey may terminate at a UI state without corresponding backend/operational behavior" — here it's the inverse: backend behavior with no customer-facing terminus).
4. **Support and refunds are structurally anticipated but not built.** Ledger has a `refund` source enum and the state machine has `REFUND_PENDING`/`REFUNDED`, but there's no initiating workflow on either side.
5. **RBAC is a flat role string, not the modeled Permission system Phase 7 requires.**
6. **The admin-framework supersession (MASTER-PROMPT §6: Next.js → Vite+React for back office) has zero code impact yet** — `apps/admin` is still Next.js today. This is expected (the ADR + migration is Phase 6/task #7, not Phase 0), noted here only so PROJECT-STATE.md reflects it as *not started*.
