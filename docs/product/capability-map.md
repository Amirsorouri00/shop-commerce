# Capability Map

> Phase 1 of `docs/program/MASTER-PROMPT.md`. Maps platform capabilities to which business line(s) consume them, distinguishing shared-spine (D) capabilities from per-line surface/policy differences (blueprint line 271). Build-status column is inherited from `docs/program/00-current-state-assessment.md` §0.2 (Line A only, today).

| Capability | Shared spine (D)? | Line A (B2C) | Line B (Merchant) | Line C (Enterprise) | Build status (Line A, per Phase 0) |
|---|---|---|---|---|---|
| Identity / auth | Core identity shared; account *kind* differs | Individual OTP login | Merchant org login (embedded panel) | Enterprise org login, likely SSO-capable later | COMPLETE (individual only) — no Organization concept yet (Phase 2 greenfield) |
| Product resolution (URL/spec → normalized product) | Shared resolution ladder; input differs | Paste one marketplace URL | Same, merchant relays on customer's behalf | Spec/BOM instead of a URL — needs a distinct intake, not just a bigger resolver (`business-lines.md` §C) | PARTIAL — resolution ladder exists, only 2 strategies wired (Phase 4 territory) |
| Quote / landed cost | Shared `QuoteEngine` | Consumer price | **Wholesaler-mode** price (source hidden, margin embedded) by default; Agent-mode transparent breakdown at higher tiers | Deposit/milestone-aware enterprise quote | COMPLETE (sandbox) for Line A's single pricing mode; wholesaler-mode pricing policy does not exist yet |

| Procurement execution | Shared `ProcurementEngine` / max-procurement-price guard | Consumer-marketplace procurement | Same engine, wholesale spread applied | B2B supplier/RFQ sourcing — Universal Adapter needs a B2B-catalog extension (`business-lines.md` §C) | COMPLETE (sandbox) for Line A's marketplace-only sourcing |

| Exception handling (price-changed, OOS, delays) | Shared state machine | Operator-side complete; **customer-facing decision UI missing** (Phase 0 §0.3.3) | Same gaps, plus needs merchant-facing relay (merchant is the customer's face, not the platform) | Same gaps, enterprise-scale (partial shipments, backorders) | PARTIAL/INCONSISTENT — see Phase 0 finding |

| Catalog / marketplace browsing | **Out of product boundary** — see `product-boundary.md` | — | — | — | Not built, not planned |

## Reading this table

- Rows marked "Shared spine" are exactly the capabilities Phase 0 found already built for Line A — the program's job for these is *generalize*, not *rebuild*.
- Columns for B and C are policy/surface deltas on the same rows, per the blueprint's own framing (line 271) — this is the concrete evidence that Line B/C really are "fast, cheap, and second/third" rather than separate builds, which is what justifies deferring them in `mvp-vs-platform.md`.
- The two rows with no shared-spine "generalize" path yet identified — money model (needs a wallet/escrow abstraction the current `Money`/ledger primitives don't have) and identity (needs Organization/Membership) — are the two highest-leverage architecture decisions for Phase 2 (accounts) and later backend-requirements work (Phase 10) to get right first, since every other B/C capability sits on top of them.
